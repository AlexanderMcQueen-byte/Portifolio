Practical Python coding: clean, readable, and testable code

Concrete tips, patterns, and short examples to help you write Python code that others (and future you) can maintain.

Alexander McQueen

Computer Science student & full-stack developer

1. Follow a consistent style

Use PEP 8 as your base. Consistent naming, spacing, and structure makes code readable instantly. Prefer descriptive names over clever short ones.

2. Keep functions small and focused

Each function should do one thing. If you can name a function in a single phrase, its intent is likely clear. Small functions are easier to test and reason about.

3. Document behavior, not implementation

Docstrings should explain the function's contract: inputs, outputs, and side effects. For example:

def normalize_name(name: str) -> str:
    """Return a lowercase, stripped version of `name`.

    Args:
      name: the input name string

    Returns:
      Normalized name.
    """
    return name.strip().lower()

4. Prefer explicitness

Use explicit conversions and clear control flow. Avoid hidden side-effects and implicit globals. Explicit code is easier to debug.

5. Write tests for behaviour

Tests are documentation and safety. Use pytest for small projects and focus tests on observable behaviour (inputs → outputs), not internal implementation.

6. Handle errors intentionally

Catch exceptions where recovery is possible and let them bubble up otherwise. Avoid blanket except: clauses; prefer catching specific exceptions.

"If your code is hard to test, it's probably doing too much."

7. Use typing where it helps

Type hints improve tooling, readability, and refactoring confidence. They don't replace tests, but they reduce simple mistakes.

8. Organize modules by feature

Group code by feature or domain (not by type). This reduces cross-module coupling and makes it easier to find related code.

9. Performance: measure first

Before optimising, profile your code. Use timeit, cProfile or sampling profilers. Often algorithmic changes beat micro-optimisations.

10. Keep dependencies minimal

Install only what you need. Prefer stdlib solutions when they are sufficient; third-party libraries add maintenance and potential security surface.
