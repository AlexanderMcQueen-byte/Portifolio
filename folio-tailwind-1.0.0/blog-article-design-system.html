Building a design system from scratch in a weekend

Tokens, components, docs — the exact process I follow to spin up a coherent design system in 48 hours.

Alexander McQueen

Computer Science student & full-stack developer

Start with a token map

Begin by defining a minimal token set: color palette, type scale, spacing units, and a couple of elevation levels. Keep it intentionally small — this reduces decision friction and prevents bikeshedding.

"A good design system makes the conscious decisions for you, so the team can focus on product problems."

Component-first, not atom-first

Identify the highest-value components used across pages (buttons, inputs, cards). Build these with tokens and document variants. Reuse beats perfection.

Docs as the API

Ship documentation alongside components: examples, dos & don'ts, code snippets. The docs are the contract between designers and implementers.

  • Tokens: centralised and versioned.
  • Components: small, composable, and documented.
  • Automation: linting, visual regression, and storybook.
